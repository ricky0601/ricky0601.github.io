2026년 9월 22일, OpenAI는 GPT-6 Sol과 Luna를, Anthropic은 Claude Opus 5.5를 발표했다. 세 모델 모두 개발 작업에 활용할 수 있지만 지향하는 작업의 크기와 가격은 다르다. 발표 수치만으로 우승자를 정하기보다, 내가 하는 작업에 어떤 모델이 맞을지 판단할 기준을 정리해 보았다.

이 글은 **출시 자료와 공식 문서에 근거한 정리**다. 세 모델에 동일한 코딩 과제를 실행해 직접 비교한 결과는 아니다. 가격과 제공 범위는 작성일 기준이며 이후 바뀔 수 있다.

## 세 모델의 위치와 가격

| 모델 | 공식 문서에서 강조하는 용도 | API 입력 / 출력 가격 |
| --- | --- | --- |
| GPT-6 Sol | 복잡한 코딩과 에이전트 워크플로 | $2 / $10 |
| GPT-6 Luna | 범위가 좁고 대량으로 처리하는 작업 | $0.10 / $0.50 |
| Claude Opus 5.5 | 장시간 이어지는 코딩과 지식 작업 | $4 / $20 |

가격은 **표준 API에서 텍스트 100만 토큰당 미국 달러** 기준이다. [Sol 모델 문서](https://developers.openai.com/api/docs/models/gpt-6-sol), [Luna 모델 문서](https://developers.openai.com/api/docs/models/gpt-6-luna), [Claude 모델 비교 문서](https://platform.claude.com/docs/en/models/overview)에 기재된 기본 입력·출력 단가를 옮겼다. 캐시, 긴 입력, 처리 방식 등에는 별도 요율이 적용될 수 있다. 구독 서비스나 GitHub Copilot의 과금과도 동일시하면 안 된다.

[OpenAI 발표](https://openai.com/index/introducing-gpt-6-sol-and-luna/)는 Sol과 Luna를 성능뿐 아니라 비용 효율을 높인 모델로 소개하며, 개선된 프롬프트 캐싱도 강조한다. [Anthropic 발표](https://www.anthropic.com/claude-opus-5-5)는 Opus 5.5가 Opus 5보다 일반적인 작업에서 비용이 약 40% 적게 든다고 설명한다. 후자는 토큰 단가만의 차이가 아니라 Anthropic이 측정한 작업당 사용량까지 포함한 주장이다.

## 가격표만으로 실전 비용을 알 수 없는 이유

같은 요구사항이라도 모델마다 출력 길이, 추론 과정, 도구 호출 횟수, 재시도 횟수가 다를 수 있다. 표의 단가는 출발점일 뿐, 작업이 끝날 때까지 쓴 **총 토큰과 시간**이 실제 비용을 결정한다. 캐시를 얼마나 재사용했는지도 에이전트 작업에서는 중요하다.

발표 벤치마크도 바로 맞대결로 읽기 어렵다. OpenAI가 제시한 코딩 평가의 주요 비교 대상에는 이전 세대 Claude 모델이 포함되고, Anthropic이 제시한 평가에는 GPT-6 Astra나 GPT-5.6 Sol이 등장한다. 평가 데이터, 에이전트 실행 환경, 추론 강도, 안전장치가 다르면 점수만 나란히 놓아 **Sol과 Opus 5.5 중 누가 더 낫다**고 결론 낼 수 없다. 두 회사의 발표에 나온 향상 폭도 각각 자사 평가와 설정에 따른 결과로 읽어야 한다.

## 개발 작업에서는 어떻게 고를까

아래는 제품 설명과 가격을 바탕으로 한 **시험 순서의 가설**이지, 직접 검증한 성능 순위가 아니다.

- 반복적이고 범위가 작은 분류·요약·간단한 코드 보조는 Luna부터 시도한다. 저렴한 단가가 장점이지만, 수정 결과를 확인하는 비용이 커진다면 다른 모델이 나을 수 있다.
- 여러 단계의 구현과 검증이 필요한 일반적인 코딩 작업은 Sol을 먼저 시도한다. 복잡한 코딩 워크플로를 목표로 한 모델이라는 점이 출발 근거다.
- 코드베이스 전반을 조사하거나 오랜 시간 이어지는 마이그레이션은 Opus 5.5도 비교 후보에 넣는다. 단가가 높은 만큼 완료율과 사람의 후속 수정량까지 함께 봐야 한다.

사용하는 제품에서 선택할 수 있는지도 확인해야 한다. [OpenAI 출시 공지](https://openai.com/index/introducing-gpt-6-sol-and-luna/)에 따르면 출시 당시 Sol·Luna는 ChatGPT Work와 Codex 및 API에서 제공됐지만 일반 Chat에는 아직 제공되지 않았다. [Anthropic은 Opus 5.5](https://www.anthropic.com/claude-opus-5-5)를 자사 플랫폼과 주요 클라우드에서 제공한다고 밝혔다. [GitHub Copilot의 Sol·Luna](https://github.blog/changelog/2026-09-22-openais-gpt-6-sol-and-gpt-6-luna-now-available/)와 [Opus 5.5](https://github.blog/changelog/2026-09-22-claude-opus-5-5-is-now-available-in-github-copilot/)도 지원 요금제가 서로 다르고 점진적으로 배포된다.

## 다음에는 무엇을 검증할까

내가 실제로 모델을 고른다면, 같은 저장소에서 접근성 오류 수정, 여러 파일에 걸친 리팩터링, 실패하는 테스트의 원인 분석을 각각 맡겨볼 것이다. 과제와 허용 도구, 추론 설정, 시간 제한을 기록하고 다음 항목을 비교해야 한다.

1. 테스트 통과와 요구사항 충족 여부
2. 사람이 다시 수정해야 하는 코드와 놓친 예외 사항
3. 완료까지 걸린 시간과 재시도 횟수
4. 캐시와 도구 사용을 포함한 실제 작업당 비용

지금 확인할 수 있는 것은 **각 모델이 어떤 작업을 목표로 출시됐고 얼마에 제공되는가**다. 어떤 모델이 내 작업에 가장 효율적인지는 같은 조건에서 직접 실행한 뒤에야 말할 수 있다.
